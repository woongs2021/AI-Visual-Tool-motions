# AI Visual Cue Studio

AI 에이전트가 활성화될 때 화면에 나타나는 **비주얼 큐(AI Visual Cue)**의 컬러·물성·크기·모션을 웹에서 조절하고, 그 결과를 **Kotlin + Jetpack Compose 코드**로 내보내는 디자인 툴입니다.

### ▶ 바로 열기: [**woongs2021.github.io/AI-Visual-Tool-motions**](https://woongs2021.github.io/AI-Visual-Tool-motions/)

설치나 빌드 없이 브라우저에서 바로 동작합니다. WebGL2를 지원하는 최신 Chrome, Edge, Safari, Firefox에서 열 수 있습니다.

---

## 주요 기능

- **프리뷰 3개 뷰**: **Adaptive Screen** 시안(전체 화면, 맨 앞) / **큐 적용 사례**(Adaptive Screen의 현재 모습과 큐를 적용한 모습을 나란히) / **전체 비교**(① 비주얼 큐와 ② 앱 적용을 나란히). 좌우 화살표, 키보드 ←/→, 드래그로 넘깁니다. 나란히 놓인 두 화면은 같은 시간축으로 동기화되어 무한 루프로 재생됩니다.
- **컨트롤 영역 너비 조절**: 컨트롤 패널과 프리뷰 사이의 바를 드래그하면 컨트롤 영역 너비를 자유롭게 바꿀 수 있습니다(더블클릭: 기본 너비, 바를 선택하고 ←/→ · Shift+←/→ · Home/End). 너비는 브라우저에 저장되며, 패널이 좁아지면 프리셋·슬라이더·물성 썸네일이 다음 줄로 넘어가 다시 배치됩니다. 물성 썸네일은 어떤 너비에서도 찌그러지지 않고 완전한 원형을 유지합니다.
- **Adaptive Screen 시안**: 맥락에 따라 화면이 스스로 재구성되는 전체 화면 루프입니다. 글자가 한 자씩 블러에서 선명해지며 쓰이고, 하단 컨트롤 바가 물방울처럼 갈라지고 합쳐져 탭으로 정리됩니다. [`adaptive_screen_loop_code/screen_loop.html`](adaptive_screen_loop_code/screen_loop.html)의 엔진을 툴로 옮겨 왔고(360 × 780dp 비율), EN / KO 토글과 재생·일시정지·타임라인 이동이 함께 동작합니다. 변하는 구간(글씨 쓰기, 하단 바 변형, 배경 전환)은 원본보다 1.5배 천천히, 더 부드러운 이징으로 움직이고, 멈춰 있는 시간은 원본 그대로입니다. 이 뷰에서는 L1/L2/L3 버튼이 S1/S2/S3(상태 이동)이 됩니다. Design 탭의 큐 설정은 이 시안이 아니라 큐 적용 사례와 전체 비교에 반영되고(컬러의 화면 배경은 이 시안에도 반영), 영상 저장은 [`render.py`](adaptive_screen_loop_code/render.py)로 합니다.
- **큐 적용 사례**: 왼쪽은 Adaptive Screen 그대로, 오른쪽은 같은 화면에 AI Visual Cue를 적용한 모습입니다. 오른쪽 화면은 상태가 바뀔 때마다 먼저 에이전트가 생각하는 로딩 단계를 거칩니다. 로딩은 상태 1~3 모두 5.8초로 같고(캡슐이 두 번 숨쉬는 시간), 캡슐의 모양·크기·블러·숨쉬기도 모든 상태에서 같습니다.
  - **로딩(생각하는 중)**: 화면의 글씨 전체가 블러로 흐려진 채 머물고, 하단 플로팅과 배경은 그대로입니다. 상단에는 로딩 큐가 나타나는데, 구 대신 가로로 두 배 긴 캡슐이고 아래쪽으로 갈수록 프로그레시브 블러(하단 80dp)로 흐려집니다. 캡슐은 숨쉬듯 원형(구와 같은 크기의 동그라미)까지 줄어들었다가 다시 원래 너비로 늘어납니다. 가로 폭이 두 배만큼 크게 변하기 때문에, 한 번 숨쉬는 데 약 2.7초(줄어드는 데 1.35초, 늘어나는 데 1.35초)가 걸리는 느린 호흡으로 하고, 양 끝에서 천천히 멈췄다가 움직이는 부드러운 곡선(코사인)으로 변합니다. 나타나자마자 이렇게 두 번 이어서 숨쉬고(5.8초 로딩), 원래 너비로 돌아온 뒤 잠깐(0.1초) 멈췄다가 그 너비 그대로 이어서 펴집니다. 캡슐 윗가장자리를 따라 보이는 가는 테두리 빛(오라의 감싸는 빛, 소프트 글로우의 림 라이트)은 원래보다 조금 더 강하게(1.4배) 하고, 범위는 캡슐 맨 위에서 30%까지는 그대로 세게 비치다가 그 아래로 서서히 줄어들어 중간(50%)에서도 충분히 이어지고 맨 아래에서 사라지게 했습니다. 옆면과 아래쪽까지 둘려 있던 테두리 빛이 위쪽에 모이고 아래로 갈수록 옅어지는 모양입니다. 몸통 색과 바깥으로 번지는 후광은 그대로이고, 큐가 전체 화면으로 퍼지는 동안 이 범위와 세기는 원래대로 돌아옵니다. 다른 물성에는 적용되지 않습니다.
  - **확산**: 캡슐이 카드 단계 없이 곧바로 전체 화면으로 쫙 펴지고(기본 1.5초에 걸쳐 천천히, 블러는 퍼지는 동안 사라짐), 그 사이 흐려져 있던 글씨는 사라지고, 새 문장은 왼쪽 화면(Adaptive Screen)과 똑같이 한 글자씩 블러에서 써집니다(프로그레시브 블러: 글자가 빠르게 나타난 뒤 블러가 천천히 걷히며 살짝 떠올라 자리를 잡아, 쓰는 지점 뒤로 부드러운 블러 꼬리가 따라옵니다). 하단 플로팅이 바뀐 뒤 큐는 사라집니다.
  - **왼쪽 화면**: 로딩 동안 그대로 머물러 있다가 오른쪽과 같은 순간에 바뀝니다(원래대로 한 글자씩 써짐). 그래서 이 뷰의 루프는 Adaptive Screen 시안보다 길고, 재생 바와 S1/S2/S3 버튼도 이 루프를 따릅니다. S 버튼은 그 상태의 로딩부터 보여 주고, 뷰를 열면 상태 1의 로딩 직전부터 재생됩니다.
  - **배경에만 그려짐**: 큐는 배경 바로 위, 글씨와 하단 플로팅 아래에 그려지기 때문에 배경만 바뀌고 글씨에는 영향을 주지 않습니다.
  - **하단 플로팅은 맨 위 레이어**: 하단 플로팅은 큐의 영향을 받지 않고 왼쪽 화면과 똑같이 보입니다. 큐는 플로팅 가장자리까지 닿고, 플로팅의 그림자만 큐 위에 드리워집니다. 하단 바는 반투명 유리라서, 바와 정확히 같은 모양(변형 중인 모양까지)으로 바 아래에만 원래 배경을 깔아 큐의 빛이 바를 통해 비치지 않게 했습니다.
  - **Design 탭 연동**: 컬러·물성·구 지름·이징·전환 시간·나타남/사라짐 값이 오른쪽 큐에 그대로 반영됩니다. 전환 시간과 나타남/사라짐은 위의 느린 속도에 맞춰 1.5배로 쓰이고(펼쳐지는 시간은 여기에 0.3초를 더 얹어 기본 1.5초), 안착 카드·리스트 관련 값은 쓰이지 않습니다. 캡슐의 가로 길이, 하단 블러, 숨쉬기 폭은 **로딩 형태**에서 조절합니다. 이 로딩과 펼쳐짐은 전체 비교의 상단 에이전트 볼(L1)에도 똑같이 쓰입니다.
- **한 사이클 모션(전체 비교)**: L1 로딩(상단에 캡슐이 나타나 5.8초 동안 두 번 숨쉼, ② 앱은 블러로 흐려짐) → L2 캡슐이 블러를 걷어내며 1.5초에 걸쳐 카드로 펴져 앱 콘텐츠 사이에 끼어들고 리스트 생성(아래 콘텐츠는 밀려 내려가고 앱은 다시 선명해지며, 하단 플로팅에서 일정 버튼이 갈라져 나옴) → L3 전체 화면 글로우: 카드의 리스트는 흐려지며 사라지고, 상단에 에이전트가 하는 말이 Adaptive Screen처럼 한 글자씩 블러에서 써진 뒤, 그 24dp 아래로 리스트 5줄이 한 줄씩 같은 방식으로 나타남(앱은 흐려지며 뒤로 물러나고, 하단 플로팅은 탭으로 정리) → 페이드 아웃(에이전트의 말과 리스트는 흐려지며 사라지고, 하단 플로팅은 처음 모양으로) → 반복. 루프는 기본 약 17.4초(KO) · 17.9초(EN)입니다.
- **Design 탭**
  - 컬러: 위에서부터 세트 → 화면 배경 → 에이전트 컬러 → 추가 색상 순서입니다. 색이 많이 들어가도록 타일을 작게 해서 한 줄에 여러 개가 놓입니다(패널 너비에 따라 자동으로 줄바꿈).
    - **세트**: 화면 배경 + 그 배경에 어울리는 에이전트 컬러 + 물성을 한 번에 바꿉니다. Meadow(원래 화면 · Azure · 오라, 기본값), Lavender(Blossom · 소프트 글로우), Sky(Indigo · 프로스티드 글래스), Sunrise(Ember · 오라), Dune(Amber · 매트 클레이), Lagoon(Mint · 워터), Blush(Rosé · 펄), Cloud(Azure · 리퀴드 메탈), Citrus(Lime · 가스), Sage(Jade · 소프트 글로우), Dusk(Indigo · 네온) 11종이고, 각 타일에는 그 세트의 에이전트가 실제 물성으로 그 배경 위에 그려집니다. 세트를 고른 뒤 셋 중 하나를 바꾸면 세트 표시만 꺼지고 나머지는 그대로 유지됩니다.
    - **화면 배경**: Adaptive Screen(시안, 큐 적용 사례의 두 화면)의 배경 그라디언트를 에이전트와 상관없이 단독으로 고릅니다. 세트와 같은 11종이고, 위 · 가운데 · 아래 색을 직접 바꿀 수도 있습니다. 모두 밝은 톤이라 화면의 글씨와 유리 하단 바가 그대로 잘 보이고, 하단 바의 그림자 색은 배경의 아래 색에 맞춰 바뀝니다(원래 화면의 분홍 그림자처럼). 상태가 바뀔 때의 배경 변화(위 색 띠가 줄고 마지막 상태가 조금 더 맑아짐)도 그대로 따라갑니다. Meadow는 원래 화면의 상태별 색을 그대로 씁니다. 유리 · 워터 물성은 바뀐 배경을 굴절해 보여 줍니다.
    - **에이전트 컬러**: 3스톱 그라데이션 에디터(칩 드래그로 위치 조절), 레퍼런스 영상에서 추출한 프리셋 3종(Azure / Blossom / Indigo)과 난색 프리셋 3종(Ember / Amber / Rosé), 그린 프리셋 3종(Mint / Jade / Lime), 방사형·선형
  - 물성 9종: 소프트 글로우, 오라(빛이 감싸며 번짐), 워터(굴절·물결), 가스(연기·성운), 네온, 프로스티드 글래스, 리퀴드 메탈, 펄, 매트 클레이 (타입별 세부 파라미터)
  - 기본 물성은 **오라**입니다. 예전 기본값이던 소프트 글로우로 저장된 설정은 한 번만 오라로 옮겨집니다(그 뒤에 직접 고른 물성은 그대로 유지).
  - 소프트 글로우에는 **샤인** 슬라이더(안쪽 광채 · 왼쪽 위 광택 점 · 얇은 테두리 빛)가 있어 기본값에서 살짝 샤이니하게 빛납니다. 0으로 내리면 광택 없는 매트한 질감에 가까워집니다.
  - 로딩 형태(큐 적용 사례 · 전체 비교): 퍼지기 전 상단 캡슐의 가로 길이(구 대비 배율, 기본 2×), 하단 프로그레시브 블러(기본 80dp), 숨쉬기 폭(숨쉴 때 원형 쪽으로 줄어드는 정도, 기본 100% = 원형까지, 0이면 멈춰 있음. 예전 '가로 숨쉬기' 값으로 저장된 설정은 뜻이 바뀌어 한 번만 기본값으로 바뀜)
  - 투명도: 물성과 상관없이 큐 전체의 불투명도를 조절
  - 크기: 구 지름(로딩 캡슐의 높이이자 숨쉴 때 줄어드는 원의 지름), 안착 높이·두께·모서리, 여백
  - 모션: 재생 속도, 전환 시간, L2 · L3 유지 시간, 나타남·사라짐, 전환 방식(모프 / 위상 회전), 이징 프리셋, 하이라이트 흔들림, 컴포넌트 간격. L1은 로딩이라 유지 시간 대신 두 번 숨쉬는 길이(5.8초)를 쓰고, 예전의 L1 유지 · 부유 진폭 · 부유 주기는 없어졌습니다.
  - 그림자: 강도 · 번짐 · 거리(카드에 드리워짐. 로딩 캡슐에는 그림자가 없습니다)
- **Code 탭**: 현재 설정이 그대로 들어간 Kotlin 파일, AGSL 셰이더, 설정 JSON을 보여주고 복사할 수 있습니다.
- **색상 변경**: 그라데이션 칩을 클릭하면 컬러 피커가 열립니다(드래그하면 위치 조절). 리스트 강조색, 리스트 카드 배경, 그림자 색, ① 프리뷰 배경도 따로 지정할 수 있고 "자동으로"를 누르면 기본 규칙으로 돌아갑니다.
- **Set as default**: 상단 버튼을 누르면 지금 설정과 보고 있는 뷰가 이 브라우저에 기본값으로 저장됩니다. 다음에 페이지를 열면 그 화면에서 시작하고, 아래 초기화 버튼들도 그 값으로 돌아갑니다. 패널 맨 아래 "처음 기본값으로"를 누르면 저장한 기본값이 지워집니다. 저장 위치는 브라우저(localStorage)라서 다른 기기나 다른 사람에게는 공유되지 않습니다.
- **초기화**: 슬라이더마다 ↺ 버튼(값을 바꿨을 때 표시), 섹션 제목 옆 "초기화", 패널 맨 아래 "전체 초기화"
- **전체 비교 화면 (SEED 디자인 시스템)**
  - **배경과 세트**: ①과 ②도 큐 적용 사례처럼 화면 배경 그라디언트와 빛 효과 위에 놓이고, 컬러의 세트와 화면 배경을 바꾸면 함께 바뀝니다. ①은 추가 색상의 "① 프리뷰 배경"을 직접 고르면 그 단색을 씁니다.
  - **② 앱 적용 화면**: [SEED Design](https://seed-design.io)(당근, Apache-2.0)의 파운데이션과 컴포넌트 스펙대로 새로 구성한 하루 일정 앱입니다.
    - 구성: 앱바(제목 · 알림 · 프로필), 칩(전체 · 일정 · 메모 · 사진 · 장소), 다음 일정 카드(배지 · 제목 · 시간과 장소 · 참석자 · "메모 보기" 버튼), 최근 항목 리스트, 하단 플로팅 바
    - 색 역할 · 글자 크기(t1~t6) · 간격(화면 여백 16) · 라운드 · 그림자는 SEED 토큰 값 그대로이고, 문구도 SEED 글쓰기 원칙(해요체, 익숙한 말, 제목과 버튼에는 마침표 없음)대로 새로 썼습니다.
    - 에이전트 볼의 카드에 밀려 내려간 리스트는 하단 플로팅 바 위에서 SEED의 스크롤 포그(fade-mask)로 부드럽게 사라집니다.
    - 일정 카드와 최근 항목 리스트는 흰색 대신 **유리**입니다. 흰색 60% 불투명도에 배경 블러(16dp)를 주고, 세트의 에이전트 컬러 그라디언트를 옅게 깔고(카드마다 그라디언트의 다른 부분), 얇은 흰 테두리를 둬서 화면 배경에 스르륵 묻힙니다. 카드 안의 버튼과 아이콘 박스는 SEED의 반투명 회색(neutral-weak-alpha)입니다.
  - **에이전트 볼이 만드는 리스트**: ✦ 반짝이와 반투명 유리 카드 대신 SEED 리스트 아이템입니다. 리스트 강조색으로 옅게 칠한 아이콘 박스와 선 아이콘(일정 · 문서 · 링크 · 말풍선 · 시계), 보통 굵기 제목과 조금 진한 회색 설명(유리 위에서 잘 읽히도록 SEED neutral-muted)으로 되어 있습니다. 행도 같은 유리여서 뒤의 에이전트 볼이 흐리게 비치고, 각 행에는 에이전트 컬러 그라디언트의 일부가 옅게 깔려 위 행부터 아래 행까지 그라디언트가 이어집니다. 전체 화면에서는 화면 여백 16, 행 높이 72, 간격 12로 놓입니다. 생성되는 Kotlin 코드(`CueComponents`)도 같은 값(반투명 표면 · 그라디언트 · 테두리)으로 바뀝니다. 배경 블러는 Compose 기본 기능에 없어서 코드에 안내 주석만 있습니다.
  - **상단 에이전트 볼(L1)**: 큐 적용 사례와 같은 로딩 캡슐입니다. 같은 함수로 그려서 모양 · 아래쪽 프로그레시브 블러 · 테두리 빛 · 5.8초 동안 두 번 숨쉬기 · 나타나는 시점과 속도까지 똑같고, 그다음 큐 적용 사례와 같은 1.5초에 걸쳐 블러를 걷어내며 펴집니다. 다만 전체 화면이 아니라 카드로 펴져 앱 콘텐츠 사이에 끼어듭니다. ①도 같은 캡슐입니다.
  - **로딩 중 앱 블러**: 에이전트가 생각하는 동안 ② 앱 화면(앱바 · 칩 · 카드 · 리스트)이 큐 적용 사례의 글씨와 같은 방식으로 1초에 걸쳐 블러(4.7dp)로 흐려지고 72%로 옅어진 채 머뭅니다. 캡슐이 펴지기 시작하면 펴지는 동안(펴짐이 끝나고 0.3초 뒤까지) 다시 선명해집니다. 휴대폰의 상태 표시줄과 하단 플로팅 바는 흐려지지 않습니다.
  - **전체 화면(L3): 에이전트의 말, 그 아래 리스트**: 큐가 전체 화면으로 펴지면 상단에 큐 적용 사례의 문장처럼 에이전트가 하는 말이 나오고, 리스트 5줄은 그 24dp 아래에 놓입니다(리스트가 하단 플로팅 바 위에서 끝나도록 문장 크기가 맞춰집니다). 리스트 내용과 이어지는 문장입니다(KO "**디자인 회의가** 30분 뒤예요. **도와드릴 수 있는 일이에요.**", EN "Your **design meeting** is in 30 minutes. **Here’s what I can do.**"). 글꼴 · 색 · 줄 간격 · 굵게 강조하는 방식은 큐 적용 사례와 같고, 크기는 큐 적용 사례(28dp)보다 조금 작은 26dp로 해서 두 언어 모두 의미 단위로 줄이 나뉘고(KO 2줄, EN 3줄) 리스트와 충분히 떨어집니다. 문장이 길어져 3줄을 넘거나 리스트에 가까워지면 맞을 때까지 글자 크기가 자동으로 줄어듭니다. 나타나는 순서와 방식은 Adaptive Screen의 글씨와 같습니다. 큐가 펴지기 시작하면 카드의 리스트는 큐 적용 사례의 이전 문장처럼 흐려지고 옅어지며 위로 사라지고, 0.63초 뒤부터 에이전트의 말이 한 글자씩(0.017초 간격) 블러 6dp에서 써지며 3.3dp 떠올라 자리를 잡습니다(글자마다 1.7초에 걸쳐 선명해져서, 쓰는 지점 뒤로 블러 꼬리가 따라오는 프로그레시브 블러). 그다음 리스트가 한 줄씩(0.2초 간격) 글자 하나처럼 같은 블러와 떠오름으로 나타납니다. L3는 마지막 줄이 다 나타난 뒤 1.2초 더 머무르고(‘L3 유지’가 그보다 길면 그만큼), 그래서 루프 길이는 문장 길이에 따라 조금 달라집니다. 그동안 뒤의 앱은 큐 적용 사례의 이전 문장처럼 흐려지며(블러 7dp) 90% 뒤로 물러나 글자가 겹쳐 보이지 않습니다. 큐가 사라질 때는 에이전트의 말도 흐려지고 옅어지며 살짝 위로 사라집니다. 리스트 글자는 두 언어 모두 잘리지 않습니다.
  - **하단 플로팅 바**: 예전 입력창 대신 큐 적용 사례의 다이나믹한 플로팅 바를 씁니다. 크기 · 반투명 유리 · 화면 배경 색 그림자 · 물방울처럼 갈라지고 합쳐지는 변형이 같고, 아이콘과 플레이스홀더만 SEED(선 아이콘, t5 · fg.placeholder)를 따릅니다. 로딩 동안 [+ · 입력창] 그대로 → 캡슐이 카드로 펴질 때 입력창에서 일정 버튼이 갈라져 나옴 → 전체 화면이 되면 탭(일정 · 메모 · 대화)으로 정리 → 큐가 사라질 때 처음 모양으로 돌아옴(이 시간만큼 루프 끝의 사라짐 구간이 약 2.5초로 길어졌습니다). 큐보다 위 레이어이고, 큐 적용 사례처럼 바 모양 그대로 배경을 깔아 큐가 바를 통해 비치지 않습니다.
  - 앱 화면과 에이전트의 말은 캔버스에 그리기 때문에 영상 내보내기에도 그대로 담깁니다. 하단 플로팅 바는 페이지와 같은 SVG를 이미지로 그려 넣습니다. SEED의 코드는 포함하지 않았고 토큰 값과 스펙만 참고했습니다. 당근의 로고 · 이름 같은 브랜드 리소스는 쓰지 않습니다. 라이선스와 사용 내역은 [`licenses/seed-design/`](licenses/seed-design/USAGE.md)에 있습니다.
- **실제 같은 문구**: ② 앱 적용 화면과 에이전트 볼이 만드는 리스트에는 실제 문구가 들어갑니다. 프리뷰 위 **EN / KO** 토글로 언어를 바꿉니다(기본 영문, Adaptive Screen 문장도 함께 바뀝니다). 생성되는 Kotlin 코드의 리스트 문구도 같은 언어로 나옵니다.
- **루프 내보내기**: 전체 비교 화면의 "⤓ 내보내기"에서 ① / ② / 전체 비교 중 하나를 골라 루프 1회를 저장합니다. (Adaptive Screen 시안과 큐 적용 사례는 내보내기 대상이 아닙니다.)
  - MP4: 720 × 1560(전체 비교는 더 넓음), 30fps, H.264. H.264 인코더가 없는 브라우저에서는 VP9로 저장
  - GIF: 360 × 780, 15fps, 무한 반복
  - 브라우저 안에서 프레임을 하나씩 렌더링해 인코딩하므로 수십 초가 걸릴 수 있습니다.
- 다크/라이트 모드, 설정 자동 저장(브라우저 localStorage)

## 구조: 하나의 상태에서 프리뷰와 코드를 함께 만든다

```
          ┌──────────── Spec (컨트롤 값 전체, JSON) ────────────┐
          │                                                      │
  타임라인 · 포즈 계산                                  코드 생성기
          │                                                      │
  WebGL2 셰이더 (GLSL ES 3.0) ◀── 같은 셰이더 소스 ──▶ AGSL (RuntimeShader)
          │                                                      │
     웹 프리뷰                                     Kotlin + Jetpack Compose
```

- 셰이더 본문은 `float2/float3/float4` 공통 문법으로 작성되어 있고, 웹에서는 매크로로 GLSL 타입에 연결하며 Android에서는 그대로 AGSL이 됩니다.
- 형태(로딩 캡슐 → 카드 → 전체 화면)는 둥근 사각형 SDF 하나로 표현하고, 레벨 사이는 파라미터 보간으로 연속 변형됩니다.
- 이징은 `cubic-bezier` 4개 숫자를 웹과 Compose `CubicBezierEasing`에 똑같이 사용합니다. 기본값은 레퍼런스 영상 리듬(약 0.3초 가속 → 0.4초 감속)에 맞춘 `0.6, 0, 0.1, 1`입니다.

## 생성 코드 사용법 (Android)

1. 툴의 Code 탭에서 **복사**를 눌러 `AiVisualCue.kt`로 프로젝트에 붙여넣습니다. 패키지명은 프로젝트에 맞게 바꿉니다.
2. 화면에서 호출합니다.

```kotlin
// 툴과 같은 무한 루프
AiVisualCueDemoLoop()

// 앱 상태로 레벨 제어 (L1은 로딩 캡슐이 숨쉬는 상태, Idle이면 페이드 아웃)
AiVisualCue(level = CueLevel.L2)

// 카드를 내 화면의 콘텐츠 사이에 끼워 넣기
AiVisualCueDemoLoop(
    spec = AiVisualCueSpec(cardTop = 326f),          // 카드가 들어갈 위치(dp)
    underlay = { insert, fullscreen, thinking ->
        MyScreen(
            pushBelowSlot = insert,
            alpha = (1f - 0.9f * fullscreen) * (1f - 0.28f * thinking),
            modifier = Modifier.blur((maxOf(thinking, 1.5f * fullscreen) * 4.7f).dp),   // 에이전트가 생각할 때 · 전체 화면일 때 흐리게 (Android 12+)
        )
    },
)
```

전체 화면(L3)에서 리스트 위에 나오는 에이전트의 말은 `AiVisualCueSpec(messageLines = listOf("…", "…"))`로 바꿉니다(툴이 나눈 줄 그대로 들어 있고, `*…*`로 감싼 말은 굵게 나옵니다). 툴과 같이 한 글자씩 블러에서 써지고, 리스트도 그 뒤에 한 줄씩 나타납니다(블러는 Android 12 이상). 리스트 문구는 `listItems`로 바꿉니다.

| 항목 | 내용 |
|---|---|
| minSdk | 26 |
| Android 13 (API 33)+ | AGSL `RuntimeShader`로 프리뷰와 같은 셰이더 사용 |
| API 26–32 | 그라데이션 `Brush`와 그림자로 근사하는 대체 경로 |
| 의존성 | Compose BOM 기본 라이브러리(ui, foundation, animation)만 사용 |

> 생성 코드는 아직 실제 Android 기기에서 컴파일·실행 검증을 거치지 않았습니다. 빌드 오류가 나면 이슈로 남겨 주세요.
