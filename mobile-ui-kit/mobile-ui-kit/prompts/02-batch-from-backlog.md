# 02 · 백로그에서 여러 앱 이어서 만들기

> 27개처럼 많을 때 쓰는 프롬프트입니다. 한 번에 다 시키지 말고 **3개씩** 진행하세요. 끝날 때마다 미리보기에서 보고 방향을 잡으면 품질이 고르게 나옵니다.

---

## [지시]
`CLAUDE.md`의 규칙, `prompts/00-project-brief.md`의 디자인 기준, `prompts/01-new-app.md`의 절차를 따르세요.

1. `apps/backlog.md`를 읽고 상태가 `todo`인 앱 중 **번호가 가장 작은 3개**를 고릅니다. 비어 있는 칸(화면 구성, 액센트 등)이 있으면 목적에 맞게 제안해서 백로그에 먼저 채웁니다.
   - 액센트는 기존 앱들과 겹치지 않게 고릅니다. 같은 계열 색이 3개 이상 몰리지 않게 합니다.
2. 앱을 **하나씩** 끝까지 완성합니다. 순서는 생성 → 마크업 → 로직 → 등록 → 검증입니다. 한 앱의 검증이 Pass가 나기 전에는 다음 앱으로 넘어가지 않습니다.
3. 3개를 마치면 index.html 검사를 **전체 화면 대상으로** Light와 Dark에서 한 번씩 다시 돌립니다. 기존 앱이 깨지지 않았는지 확인하기 위해서입니다.
4. `node scripts/capture.mjs --theme=both --main`으로 대표 화면을 뽑고, 새 3개의 PNG를 열어 확인합니다.
5. 백로그 상태를 갱신하고, 아래 형식으로 보고한 뒤 **멈춥니다**.

```
완료: 04 Habit Tracker · 05 … · 06 …
검사: Light N/N Pass · Dark N/N Pass
캡처: captures/…
공통 파일 변경: 없음 | (있으면 무엇을, 왜)
다음 후보: 07 … · 08 … · 09 …
```

## 일관성 체크 (앱마다)
- 앱 바 구성(뒤로가기 · 제목 · 메뉴)과 하단 주요 버튼 위치는 모든 앱이 같습니다.
- 카드 반경 16, 좌우 24, 섹션 간격 24 또는 32, 카드 사이 간격 12를 지킵니다.
- 큰 숫자·히어로 요소는 화면에 하나만 둡니다.
- 데모 데이터에는 DEMO 표시를 하고, 수치에는 근거(몇 개 중 몇 개)를 붙입니다.
- 다크 모드에서도 같은 위계로 읽혀야 합니다.

[번역]
- 화면이 끝나면 `prompts/08-translation.md` 순서대로 `scripts/i18n/ko.js`에 한국어를 넣고 `npm run i18n-check`를 통과시킨다. 한국어로도 390×844 검사를 통과해야 완료다.
