# 07 · 프로토타입(PoC) 점검과 시연 준비

> 시나리오 화면이 다 모였을 때, 실제로 눌러 보며 시연할 수 있는 상태로 다듬을 때 씁니다.

---

## [지시]
세 시나리오(또는 `<app-id>`)의 프로토타입을 시연할 수 있는 수준으로 점검하고 다듬으세요. 새 기능은 추가하지 않고, **이미 있는 흐름이 끊김 없이 동작하는 것**이 목표입니다.

1. **자동 점검**
   - `node scripts/walkthrough.mjs`를 실행합니다. 실패한 단계가 있으면 원인을 고칩니다. 테스트를 고쳐서 통과시키지 않습니다.
   - `index.html`에서 Light와 Dark 각각 "Run check on all N screens"를 실행해 모두 Pass인지 확인합니다.
2. **직접 눌러 보기** (`index.html`의 ▶ Play로 확인합니다)
   - 시나리오를 처음부터 끝까지 두 번 따라갑니다. 한 번은 정상 흐름, 한 번은 중간에 Back과 다른 선택을 섞습니다.
   - 확인할 것:
     - 막다른 화면(나갈 버튼이 없음)이 없는지
     - Back이 온 곳으로 돌아가는지
     - 자동 진행(스캔, 처리)이 뒤로가기 기록에 남지 않는지
     - 공유 데이터(선택, 체크, 새 항목)가 다른 화면에 반영되는지
     - 비활성 버튼에 이유가 보이는지
3. **상태 일관성:** 한 화면에서 바꾼 값이 다른 모든 화면에서 같게 보여야 합니다(점수, 합의율, 회의 시간 등). 데모 수치에는 DEMO 표시와 근거("5개 중 3개")가 있어야 합니다.
4. **폰에서 시연**
   - PC에서 `python3 -m http.server 8080 --bind 0.0.0.0`을 실행하고, 같은 Wi-Fi의 폰에서 `http://<PC IP>:8080/<시나리오>-home.html`을 엽니다.
   - 터치 영역, 키보드가 올라올 때 입력창이 가려지는지, 스크롤, 시트 닫기(바깥 탭)를 확인합니다.
   - 시연 전에는 각 화면의 메뉴 → Reset demo data로 초기화합니다. ▶ Play를 눌러도 초기화됩니다.
5. **캡처와 공유**
   - `node scripts/capture.mjs --theme=both --main`으로 모든 화면의 기본 상태를 뽑습니다.
   - `flows.html`을 열어 흐름 보드를 확인합니다. 테마 버튼으로 라이트와 다크를 전환할 수 있습니다.
6. 고친 것, 남은 한계(데모라서 안 되는 것), 시연 순서 추천(화면 번호 순)을 짧게 보고합니다.

## 범위 (PoC)
- **하는 것:** 주요 화면 사이 이동, 핵심 인터랙션, 상태 공유, 데모 데이터, 라이트·다크, 접근성 기본(이름, 포커스, 44px)
- **하지 않는 것:** 실제 API(마이크, 하드웨어, 결제, 서버, 로그인), 오류·빈 상태 전체, 설정 화면, 다국어, 오프라인 저장 이상의 데이터 관리
